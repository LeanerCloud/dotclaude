# Disk Cleanup

Audit, classify, protect, clean, report. Tenet 9 (AGENTS.md) holds and no space target overrides it: only MERGED items are removed unprompted; every REBUILDABLE or UPSTREAM deletion needs per-item user confirmation (decision doc, `ask-user.sh`, per "Asking the user" in AGENTS.md). Delete from exact paths, with a logged reason.

## Reports (maintained every pass)

Directory `~/.claude/reports/disk-cleanup/` (never committed):

| File | Content |
|------|---------|
| `STATUS.md` | one row per pass: free before/after, GB reclaimed, PRs opened, notes |
| `INVENTORY.md` + `*.tsv` | latest audit, generated by `scripts/disk-audit.sh` |
| `UNIQUE-WORK.md` | each item with unique work and its protection (PR, branch, bundle), verified, deleted |
| `ACTIONS.md` | every deletion: time, path, size, class, evidence, result |
| `NEEDS-HUMAN.md` | items not safe to auto-delete, with the reason |

Update them as you go, not at the end; a crashed run must be resumable from them. Skip decisions already recorded unless the item's state changed.

## Never touched

`~/.ssh`, `~/.gnupg`, `~/.claude/backups/`, `~/.claude/reports/`, password stores, credential dirs, browser profiles and data, photos, documents, Downloads and other personal media. In `~/.claude` protect config, skills, memory, plans, decisions, `projects.md`, `local-paths.md`; its work areas (`worktrees/`, `work/`, tmp dirs) are in scope. Also keep any build dir of a branch checked out in a live worktree (PID, lock or recent mtime; `multi-agent-comms`).

## Steps

1. **Audit** (read-only): `bash ~/.claude/scripts/disk-audit.sh`. Run it in the background; it can take minutes. It writes `INVENTORY.md` and TSVs of top-level sizes, every repo/worktree (dirty files, unpushed commits, remotes, size) and rebuildable candidates. Scanned repos are untrusted: the script runs git with fsmonitor and hooks disabled and skips `git status` in repos whose local config defines `filter.*.clean`/`process` (dirty column "skipped: filter config"), and drops paths containing control characters into `rejected-paths.log`; list those in `NEEDS-HUMAN.md`. Run every git command in a repo you did not create with `GIT_CONFIG_NOSYSTEM=1 GIT_OPTIONAL_LOCKS=0 git -c core.fsmonitor=false -c core.hooksPath=/dev/null -C <repo> ...`, and only after the filter precheck `GIT_CONFIG_NOSYSTEM=1 GIT_OPTIONAL_LOCKS=0 git -c core.fsmonitor=false -c core.hooksPath=/dev/null -C <repo> config --local --includes --get-regexp '^filter\..*\.(clean|process)$'` (and the same with `--worktree`) returns nothing; a repo's own config can execute commands. Plain `git` there is forbidden.
2. **Classify** each item:
   - **MERGED** (safe): PR MERGED and the tip is the PR head or an ancestor, clean tree, no lock or live owner. Do not reimplement this; run `~/.claude/scripts/reclaim-merged-worktrees.sh --repo <main-checkout> --apply --branch <b>` (report first without `--apply`). This is the only unprompted deletion.
   - **REBUILDABLE** (confirm per item): build output, caches, `node_modules`, venvs, anything regenerable from source or a lockfile. Native pruners (`cargo`/`npm` cache clean) beat `rm`; `docker`/`podman system prune`, `journalctl --vacuum-size` and `coredumpctl` cleanups delete volumes or logs, so they need confirmation too. Never touch the Go build cache by any means here (`go clean -cache`, `rm`): it races the go-build-cache trimmer and the disk guard.
   - Never run `git status` (or any git command that runs filters) in repos the audit marked "skipped: filter config"; list them in `NEEDS-HUMAN.md`.
   - **UPSTREAM** (confirm per item): every local ref, stash and commit exists on a remote, verified by a network check this turn (not only local remote-tracking refs; see "Network git" below), and the tree is clean (`git rev-list --count --all --not --remotes` is 0, `git stash list` empty, `git status --porcelain --ignored` shows nothing except build output). Ignored non-build files (`.env`, notes) make it UNIQUE.
   - **UNIQUE**: unpushed commits, dirty or untracked work, stashes, remote-less branches, ignored files that are not build output. Never deleted before step 3.
3. **Protect UNIQUE work** and log it in `UNIQUE-WORK.md`:
   - Scan for secrets first (gitleaks or grep) and redact home paths, usernames and hostnames from anything that leaves the machine.
   - Choose the remote: `origin`, an existing fork, the upstream's fork, or the sibling worktree's remote. Creating a fork or pushing unique work is publication: get user confirmation first, including for `gh repo fork`.
   - Darling-looking repos (remote or path matches `darling`/`darlinghq`): open a PR to upstream when the work is worth upstreaming; skip WIP noise, duplicates and already-upstreamed work and record why. One concern per PR, up to 400 lines, grouped by topic. Open and watch (`ci-watch`, `cr-loop`), never merge.
   - Other repos: push to a fork or remote branch; PR only if it makes sense.
   - If pushing is impossible, write a `git bundle` to `~/.claude/backups/`. Anything unresolved goes to `NEEDS-HUMAN.md`.
   - An item counts as protected only after you verify the PR or branch exists on the remote (re-check with `gh` or the "Network git" command this turn).
4. **Clean**: delete MERGED items, and REBUILDABLE or UPSTREAM items the user confirmed, by exact path (no globs, no shared dirs such as `build-master`), `git worktree remove` without `--force`, then prune refs. Re-check the item's state immediately before deleting; skip it if it changed since classification. Log each action in `ACTIONS.md`.
5. **Standardise work dirs** so later sweeps can classify them: new temp work (darling prefixes and profiles, build dirs, scratch) goes under `~/.claude/work/<project>/{builds,profiles,prefixes,tmp}`, worktrees stay in `~/.claude/worktrees/`. Record each in a registry TSV (project, owner branch or PR, created, rebuild command) and note paths in `local-paths.md`. Move existing dirs only when safe; otherwise list them.
6. **Report**: append the pass row to `STATUS.md` (df before/after, GB per class, PRs opened, forks created, skipped items and why). Repeat from step 1.

## Network git

Repo-local config can run commands on connect. In a repo you did not create, run `ls-remote` only if both hold, else the item is UNIQUE and goes to `NEEDS-HUMAN.md`:

1. `config --local --includes --get-regexp` and the same with `--worktree`, with the hardened prefix, return nothing for `'^(core\.sshcommand|core\.gitproxy|core\.askpass|remote\..*\.proxy|url\..*\.(insteadof|pushinsteadof)|credential\..*|protocol\..*)$'` (git lowercases keys, so the match is effectively case-insensitive).
2. Every `remote.*.url` is plain `https://`, `ssh://` or scp-style `git@host:path`.

Then: `GIT_CONFIG_NOSYSTEM=1 GIT_OPTIONAL_LOCKS=0 GIT_TERMINAL_PROMPT=0 GIT_ASKPASS=true SSH_ASKPASS=true git -c core.fsmonitor=false -c core.hooksPath=/dev/null -c core.sshCommand=ssh -c core.gitProxy= -c credential.helper= -c protocol.ext.allow=never -c protocol.file.allow=never -C <repo> ls-remote <remote>`.

## Darling notes

Darling builds are slow to redo, so keep the build dir of the active branch and delete only those of merged or abandoned ones. Prefer a shared ccache over duplicated per-worktree build trees.
